## 3. Per-Stage Analysis & Implementation Resolution

### 3.1 Dilated Convolution (`src/models/a2/model/dynamic/process.rs` → `process_single_frame_depthwise_avx2`)

#### **Vectorization status: PARTIALLY VECTORIZED (unrolled scalar)**

The depthwise AVX2 kernel (symbol at line 804,718) uses an 8-way unrolled scalar pattern:

```asm
vmulss (%rdx,%r8,4), %xmm1, %xmm1
vaddss %xmm1, %xmm0, %xmm0
vmulss (%rdx,%rsi,4), %xmm1, %xmm1
vaddss %xmm1, %xmm0, %xmm0
; ... 6 more unrolled iterations
```

This is optimal for the depthwise case (`groups = channels = bottleneck`), where horizontal packing across channels would require gather/scatter or expensive shuffles. The unrolling depth (8-way) saturates the latency of `vmulss` (4 cycles on Zen 4 / Golden Cove).

Evidence of effective optimization:

- `prefetcht0` instructions issued for upcoming cache lines.
- Zero overhead from `vzeroupper` within the inner loop.
- No register spills to stack within the hot loop body.

**Assessment: Optimal.** No actionable optimization for depthwise conv. Standard (non-depthwise) conv uses the `grouped_conv1d_single_frame_simd` kernel which uses packed FMA.

### 3.2 Mixin GEMV (`src/models/a2/model/dynamic/process.rs`)

#### **Initial status: FULLY SCALAR (Baseline Profiling)**

The baseline flat path (`mixin_groups ≤ 1`) and grouped path originally remained scalar:

```asm
vxorps  %xmm0, %xmm0, %xmm0           ; zero accumulator
vaddss  (%rcx,%rbx,4), %xmm0, %xmm0   ; load 1 weight
vmovss  %xmm0, 864(%rsp)              ; store to stack (!)
vaddss  4(%rcx,%rbx,4), %xmm0, %xmm0  ; load next weight
vmovss  %xmm0, 868(%rsp)              ; stack spill
; ... 16 separate scalar loads
```

Critical baseline observations:

1. **Each weight loaded individually** with `vaddss` — no `vmovups` for bulk loads.
2. **Stack spills present** (`vmovss %xmm0, N(%rsp)`): intermediate results spilled to stack, then reloaded later.
3. **No FMA**: No `vfmadd231ps` or `vfmadd132ps` instructions detected in the mixin pass.

**Impact**: Mixin GEMV is a `z_out_ch × cond_size` matrix-vector multiply.

- Typical A2Dyn Gated (bottleneck=8, cond=1): 8 FMA ops.
- Multi-cond (cond=3): 24 FMA ops per frame per layer.
- A2Dyn Blended with head1x1 (z_out_ch=16): 48 scalar ops per frame.
- With 30 layers × 64 frames × 24 ops = 46,080 scalar multiply-adds per block.

**Resolution (T4.3 — Implemented & Verified)**:

- Mixin weights are transposed in `build.rs` to col-major `[in_pg][out_per_g]` per group.
- `process.rs` performs 8-wide AVX2 FMA broadcasting each condition channel over contiguous output weights (`_mm256_fmadd_ps`), eliminating scalar loads and stack spills.

### 3.3 Activation and Gating (`src/models/a2/model/dynamic/process.rs`)

**Vectorization status: VECTORIZED (via `SimdMath` trait)**

Both `apply_gating_simd::<M>` and `apply_blending_simd::<M>` are dispatched through the `SimdMath` trait, which monomorphizes to AVX2/AVX-512 code with packed SIMD. These use `vmulps`, `vaddps`, and FMA variants.

Element-wise activation also uses `apply_simd::<M>` from the trait.

**Assessment: Optimal.** The `SimdMath` abstraction surfaces vectorized element-wise operations.

### 3.4 Head 1×1 Projection / Accumulation (`src/models/a2/model/dynamic/process.rs`)

#### **Initial status: FULLY SCALAR**

The baseline grouped head1x1 projection originally executed as a scalar loop:

```rust
for oc in grp * ch_per_group..(grp + 1) * ch_per_group {
    let mut sum = head1x1_b[oc];
    for ic in 0..h1_in {
        sum += head1x1_w[oc * h1_in + ic] * z_scratch[grp * h1_in + ic];
    }
}
```

For bottleneck=8, head_accum_size=8, h1_in=8: 64 FMA ops per frame per layer. With 30 layers × 64 frames: 122,880 scalar MUL+ADD per block.

**Resolution (T4.2 — Implemented & Verified)**:

- Weights stored row-major `[head_accum_size][h1_in]` (transposed in `build.rs`).
- `process.rs` vectorizes the inner dot product in 8-wide SIMD steps (`_mm256_fmadd_ps`), with lane extraction preserving exact left-to-right accumulation order for deterministic numeric parity.

### 3.5 L1×1 Residual Sum (`src/models/a2/model/dynamic/process.rs`)

#### **Status: FULLY SCALAR (Baseline Profiling)**

The baseline col-major loop and grouped path originally remained scalar:

```rust
for oc in 0..channels {
    let mut sum = l1x1_b[oc];
    for ic in 0..bottleneck {
        sum += l1x1_w[ic * channels + oc] * z_scratch[ic];
    }
}
```

For bottleneck=8, channels=8: 64 FMA ops per frame per layer. With 30 layers × 64 frames: 122,880 scalar ops per block.

**Resolution (T4.2 — Implemented & Verified)**:

- Dense L1×1 weights stored col-major `[bottleneck][channels]`.
- Each `ic` row provides `channels` contiguous weights, enabling 8-wide SIMD across output channels with broadcast inputs (`_mm256_loadu_ps` + `_mm256_fmadd_ps`).
