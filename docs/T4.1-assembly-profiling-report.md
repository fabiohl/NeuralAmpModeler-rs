//! ## 3. Per-Stage Analysis
//!
//! ### 3.1 Dilated Convolution (`process.rs:457-461` → `process_single_frame_depthwise_avx2`)
//!
//! **Vectorization status: PARTIALLY VECTORIZED (unrolled scalar)**
//!
//! The depthwise AVX2 kernel (symbol at line 804,718) uses an 8-way unrolled
//! scalar pattern:
//! ```asm
//! vmulss (%rdx,%r8,4), %xmm1, %xmm1
//! vaddss %xmm1, %xmm0, %xmm0
//! vmulss (%rdx,%rsi,4), %xmm1, %xmm1
//! vaddss %xmm1, %xmm0, %xmm0
//! ; ... 6 more unrolled iterations
//!```
//!
//! This is optimal for the depthwise case (`groups = channels = bottleneck`),
//! where horizontal packing across channels would require gather/scatter or
//! expensive shuffles. The unrolling depth (8-way) saturates the latency of
//! `vmulss` (4 cycles on Zen 4 / Golden Cove).
//!
//! Evidence of effective optimization:
//! - `prefetcht0` instructions issued for upcoming cache lines.
//! - Zero overhead from `vzeroupper` within the inner loop.
//! - No register spills to stack within the hot loop body.
//!
//! **Assessment: Acceptable.** No actionable optimization for depthwise conv.
//! Standard (non-depthwise) conv uses the `grouped_conv1d_single_frame_simd`
//! kernel which does use packed FMA.
//!
//! ### 3.2 Mixin GEMV (`process.rs:470-515`)
//!
//! **Vectorization status: FULLY SCALAR — PRIMARY TARGET**
//!
//! The flat path (`mixin_groups ≤ 1`, lines 490-498) and grouped path
//! (lines 499-514) both remain scalar. Assembly evidence from the per-frame
//! body (lines ~585,150–585,250):
//! ```asm
//! vxorps  %xmm0, %xmm0, %xmm0    ; zero accumulator
//! vaddss  (%rcx,%rbx,4), %xmm0, %xmm0   ; load 1 weight
//! vmozss  %xmm0, 864(%rsp)       ; store to stack (!)
//! vaddss  4(%rcx,%rbx,4), %xmm0, %xmm0  ; load next weight
//! vmozss  %xmm0, 868(%rsp)       ; stack spill
//! ; ... 16 separate scalar loads
//!```
//!
//! Critical observations:
//! 1. **Each weight loaded individually** with `vaddss` — no `vmovups` for bulk loads.
//! 2. **Stack spills present** (`vmovss %xmm0, N(%rsp)`): intermediate results
//!    spill to stack, then reloaded later. This suggests LLVM could not keep
//!    the full output vector in registers.
//! 3. **No FMA**: No `vfmadd231ps` or `vfmadd132ps` instructions detected.
//!
//! **Impact**: Mixin GEMV is a `z_out_ch × cond_size` matrix-vector multiply.
//! For typical A2Dyn Gated (bottleneck=8, cond=1): 8 FMA ops (negligible).
//! For multi-cond (cond=3): 24 FMA ops per frame per layer.
//! For A2Dyn Blended with head1x1 (z_out_ch=16): 48 scalar ops per frame.
//!
//! With 30 layers × 64 frames × 24 ops = 46,080 scalar multiply-adds per block.
//!
//! **Recommendation (T4.3)**: Transpose mixin weights to row-major layout in
//! `builder.rs` and use `SimdMath::gemv_overwrite` with 8-wide AVX2 FMA.
//!
//! ### 3.3 Activation and Gating (`process.rs:536-556`)
//!
//! **Vectorization status: VECTORIZED (via `SimdMath` trait)**
//!
//! Both `apply_gating_simd::<M>` and `apply_blending_simd::<M>` are dispatched
//! through the `SimdMath` trait, which monomorphizes to AVX2 code with packed
//! SIMD. These use `vmulps`, `vaddps`, and FMA variants.
//!
//! Element-wise activation also uses `apply_simd::<M>` from the trait.
//!
//! **Assessment: Optimal.** The `SimdMath` abstraction correctly surfaces
//! vectorized element-wise operations.
//!
//! ### 3.4 Head 1×1 Projection / Accumulation (`process.rs:565-616`)
//!
//! **Vectorization status: FULLY SCALAR — SECONDARY TARGET**
//!
//! The grouped head1x1 projection (lines 580-589) remains scalar:
//! ```rust
//! for oc in grp * ch_per_group..(grp + 1) * ch_per_group {
//!     let mut sum = head1x1_b[oc];
//!     for ic in 0..h1_in {
//!         sum += head1x1_w[oc * h1_in + ic] * z_scratch[grp * h1_in + ic];
//!     }
//! }
//!```
//!
//! For bottleneck=8, head_accum_size=8, h1_in=8: 64 FMA ops per frame per
//! layer. With 30 layers × 64 frames: 122,880 scalar MUL+ADD per block.
//!
//! **Recommendation (T4.2)**: Vectorize with `chunks_exact(8)` over the
//! weight rows, using 8-wide FMA on the inner product (bottleneck dimension).
//!
//! ### 3.5 L1×1 Residual Sum (`process.rs:618-655`)
//!
//! **Vectorization status: FULLY SCALAR — TERTIARY TARGET**
//!
//! The col-major loop (lines 624-629) and grouped path (lines 632-645)
//! both remain scalar:
//! ```rust
//! for oc in 0..channels {
//!     let mut sum = l1x1_b[oc];
//!     for ic in 0..bottleneck {
//!         sum += l1x1_w[ic * channels + oc] * z_scratch[ic];
//!     }
//! }
//!```
//!
//! For bottleneck=8, channels=8: 64 FMA ops per frame per layer.
//! With 30 layers × 64 frames: 122,880 scalar ops per block.
//!
//! The `ic * channels` stride in weight access (`l1x1_w[ic * channels + oc]`
//! = stride-8) is unfavorable for cache but LLVM can still pack this.
//!
//! **Recommendation (T4.2)**: Vectorize with `chunks_exact(8)` on the output
//! channel loop, using 8-wide FMA over the bottleneck dimension.
//!
